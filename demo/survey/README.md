# 설문 스튜디오

프로젝트 루트에서 `npm run dev` 실행 후 `/survey/`에 접속합니다.
외부 프레임워크와 추가 의존성 없이 `src/index.js`의 미니 리액트 공개 API를 사용합니다.
npm run dev -- --host 127.0.0.1 --port 4173
http://127.0.0.1:4173/survey/

## 동작 흐름

1. `FunctionComponent(App).mount()`가 빈 컨테이너에 화면을 만듭니다.
2. 루트의 `useState`가 초안, 적용된 설문, 선택 질문, 응답, 버전 이력, 검증 상태를 관리합니다.
3. 입력 이벤트가 루트 상태를 바꾸면 컴포넌트가 다시 실행됩니다. 자식 함수는 props만 받아 VNode를 반환합니다.
4. 미니 리액트가 이전·다음 VNode를 diff하고 applyPatches로 변경한 DOM만 반영합니다. 이벤트는 외부 위임으로 연결하며 VNode에 함수를 저장하지 않습니다.
5. HTML 편집은 비활성 template에서 파싱한 뒤 `domToVNode`로 변환합니다. 공백과 주석을 유지하며, 하나의 루트와 문서용 태그·속성을 허용합니다. 스크립트·이벤트 속성·폼 요소는 설명 HTML에서 허용하지 않습니다. 폼은 질문 설정으로 추가합니다.
6. 변경 적용 시 제목·선택지·HTML을 검증합니다. 실패하면 실제 응답 화면과 이력을 유지합니다. 성공하면 설문 스냅샷을 저장하고 이후 분기 기록을 제거합니다.
7. 버전 이동 시 초안과 적용 설문을 함께 복원하고 응답을 초기화합니다. 단순 적용에서는 같은 질문 ID·같은 유형의 유효한 응답을 유지합니다. 삭제된 질문·선택지의 응답은 제거됩니다.

## Hooks와 입력 처리

- `useMemo`: 적용 설문과 응답이 바뀔 때만 진행률과 필수 응답 완료 여부를 계산합니다.
- `useEffect`: 초안을 localStorage에 저장하고, Ctrl/⌘+Enter 단축키를 연결합니다. cleanup은 이전 키보드 리스너를 제거합니다. 저장 공간 오류에도 편집을 계속할 수 있습니다.
- 입력 중에는 같은 노드를 유지해 포커스를 보존합니다. 질문 선택 및 버전 복원 시 편집 영역이나 응답 영역의 래퍼 태그를 교체해 브라우저의 dirty value/checked 프로퍼티를 초기화합니다. 기존 VNode·Patch 명세는 확장하지 않습니다.
- 체크박스 그룹의 필수 검증은 그룹 중 하나 이상 선택하는 규칙이며, 각 항목에 required를 붙이지 않습니다.
- 저장은 초안만 대상으로 합니다. 실제 응답 수집 서버와 영구 버전 이력은 포함하지 않습니다. 응답과 버전 이력은 새로고침하면 초기화됩니다.

## 확인할 시나리오

- 단답형·객관식·체크박스 전환, 질문 추가·삭제·순서 변경, 선택지 추가·삭제.
- 질문 제목 수정 후 적용해 같은 유형의 응답이 유지되는지 확인.
- 선택한 선택지를 삭제한 뒤 적용해 해당 응답이 사라지는지 확인.
- 필수 질문을 비운 채 응답 확인 → 오류 표시 → 응답 후 다시 확인 → 요약 표시.
- HTML에 목록·표·details·주석·공백을 추가하고 태그 교체·속성 변경을 확인.
- 빈 HTML·복수 루트·허용하지 않은 태그 입력 시 실제 응답 화면과 이력 유지.
- 되돌리기·다시 실행으로 초안과 응답 화면 복원. 과거 버전에서 적용하면 이후 이력 제거.
- 체크한 응답이 버전 이동 후 실제 DOM에서도 해제되는지 확인.
- 새로고침 후 초안 복원, 손상된 저장 데이터와 저장 공간 오류 처리.

전체 검증은 프로젝트 루트의 `npm test`, `npm run lint`, `npm run format:check`로 실행합니다.

## 추가 변경: 질문 카드 드래그 정렬

- 왼쪽 질문 카드를 잡아 다른 카드의 위쪽 또는 아래쪽에 놓으면 질문 순서가 바뀝니다. 손잡이와 잡기 커서, 드래그 중 투명도, 삽입 위치 선으로 이동 위치를 표시합니다.
- 질문 번호 `01`, `02` 등은 배열의 현재 위치에서 계산하므로 이동 직후 새 순서로 다시 표시됩니다. 질문 목록 상단의 숫자는 질문 총개수입니다.
- 루트 상태의 `drag`가 이동할 질문 ID와 대상 위치를 관리합니다. 드롭할 때만 초안 배열을 재정렬하며, DOM을 직접 옮기지 않고 기존 미니 리액트의 Diff·Patch를 사용합니다. `MOVE` 연산이나 VNode 명세 변경은 없습니다.
- 질문 ID·내용·현재 선택은 유지됩니다. 실제 응답 화면은 기존 정책대로 변경 적용 후 바뀌고, 같은 유형의 유효한 응답은 ID 기준으로 유지됩니다. 적용한 순서는 History로 복원할 수 있습니다.
- 자기 자신에게 드롭하거나 목록 밖에서 놓아 취소하면 순서가 바뀌지 않습니다. 외부 텍스트를 드롭해도 질문이 이동하지 않습니다.
- 카드 본문은 데스크톱 HTML Drag and Drop을 사용합니다. `⋮⋮` 손잡이는 Pointer Events와 포인터 캡처로 이동을 처리하므로 터치 입력도 지원합니다. 기존 위·아래 버튼은 키보드 대안으로 유지합니다.
- 확인 방법: 첫 질문을 마지막 카드 아래로 이동 → 번호가 `01`부터 다시 표시되는지 확인 → 변경 적용 → 응답 순서와 답변 유지 확인 → 되돌리기로 이전 순서 복원. 역방향 이동·자기 자신 드롭·취소도 확인합니다.
- 키보드 이동 보완: 목록 카드에 포커스를 두고 `↑`·`↓`를 누르면 해당 질문이 한 칸씩 이동하며 번호와 포커스도 같은 질문을 따라갑니다. 편집 패널의 `↑ 위로`·`↓ 아래로` 버튼도 같은 이동 함수를 사용합니다. 첫 질문의 위로 버튼과 마지막 질문의 아래로 버튼은 비활성화합니다. 입력창 안의 방향키 동작은 가로채지 않습니다.
- 버튼 배치 변경: `변경 적용`을 상단 소개 영역에서 이력 도구 모음으로 옮겨 `되돌리기 → 현재 버전 → 다시 실행 → 변경 적용` 순서로 배치했습니다. 좁은 화면에서는 버튼 간격을 줄이고 필요한 경우 줄바꿈합니다.
